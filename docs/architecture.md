# angzarr-router architecture

angzarr-router is one dispatch engine — routing commands and events to
business handlers, rebuilding state, fanning out, mapping errors —
written in Rust and exposed over a C ABI to hand-written bindings in five
languages. Code generated by `angzarr codegen <language>`
([angzarr-cli](https://github.com/angzarr-io/angzarr-cli)) targets these
bindings. The router has no transport: each host process still serves the
coordinator's gRPC services itself and hands the framework messages to the
router.

## Where it sits today

- **Consumers.** angzarr-cli's emitters generate wiring against
  `bindings/<language>`; the conformance fixtures in this repo are the
  first consumer of that generated code. Python is client-python's: this
  repo carries no Python binding.
- **client-rust** dispatches through `crates/router`'s Rust-native API (no
  FFI) and has no engine of its own. That API (`Rebuilder`,
  `AggregateDispatch` with commands and facts, `SagaDispatch`,
  `ProcessManagerDispatch` with `select_process_managers`/`merge_response`,
  `ProjectorDispatch`, `RouterBuilder`/`Router`/`CommandHandlers`,
  `CodedError`, and the wire types re-exported as `pb`) is
  therefore a public contract, documented on each item; components may be
  registered boxed (`Box<dyn CommandHandler>` and so on).
- **Not consumers (yet).** The other `angzarr-client-*` libraries still
  carry their own engines (client-go `engine*.go`, client-python
  `angzarr_client/router/`). Until they retire, the engine semantics exist
  in this repo AND in each of them; the shared contract is the semantics
  table below and the angzarr-project feature suite, not shared code.

## Layers

```
conformance/proto (component declarations)
        │  angzarr codegen <lang>
        ▼
generated wiring  ── typed seam + Register<Component>(router, handler)
        │
bindings/<lang>    ── registry of callback_id → typed invoker, one trampoline;
        │             stateless (the router owns every state)
        │  C ABI (crates/router-ffi: 14 extern "C" fns)
        ▼
crates/router-ffi  ── descriptor → core tables, component claims/routing,
        │             router-held state and projections
        ▼
crates/router      ── Rebuilder, AggregateDispatch, SagaDispatch,
                      ProcessManagerDispatch (+ co-resident selection),
                      ProjectorDispatch, CodedError
```

### crates/router (core)

Every dispatch rule lives here and is mutation-tested
(`just mutation-test`). Business payloads are opaque `Any`s; the core
calls thunks keyed by fully-qualified type name.

### crates/router-ffi (C ABI)

The exported surface (see `crates/router-ffi/src/lib.rs`):
`angzarr_abi_version`, `angzarr_buf_alloc`, `angzarr_buf_release`,
`angzarr_router_new`, `angzarr_router_free`, per component kind a
`register_*` and a `dispatch*` entry point (aggregate, projector, saga,
process manager), and `angzarr_router_component_descriptors`, which
answers every registered component's registration hello (the spec's
`ComponentDescriptor`, built by the router; the host only sends it) (ABI
version 4). The aggregate's `dispatch` takes a
`ContextualCommand` whose page carries a command or a fact and answers a
`CommandHandlerResponse`; the saga's takes the source `EventBook`. A component is registered from a serialized descriptor
(`proto/io/angzarr/router/ffi/v1/abi.proto`) listing `(fq_type,
callback_id)` entries; every callback goes through one host function
`angzarr_cb(callback_id, type_url, payload, aux, out)`.

The registry owns the component claims, which are mutation-tested with the
core:

- aggregates register into the core's `CommandHandlers`, the same table
  the Rust-native `Router` uses: a command routes by (cover domain, command
  type), several aggregates may share a domain, and a second claim of one
  (domain, command type) is refused at registration
  (`DUPLICATE_COMMAND_HANDLER`); a sole aggregate claims every domain;
- a router hosts at most one projector (one `Projection` per `EventBook`);
- a saga source routes to every saga whose input domain matches;
- a process-manager request routes through the core's
  `select_process_managers`.

### bindings/<language>

Go (cgo), Java (FFM), C# (P/Invoke), TypeScript (koffi),
C++ (static link). **Parked:** every binding is still written against ABI 3
and the pre-latest-spec protos; CI does not build them until each is ported
to ABI 4. Each binding checks `angzarr_abi_version` against the
version it was written for before first use. Every callback is stateless: the
router owns aggregate and process-manager state and projector projections,
so a binding keeps no state of any kind.

## Engine semantics

| Semantic | Contract |
|---|---|
| State rebuild | Snapshot applies first; pages at or below a LOADED snapshot's sequence never re-apply (a snapshot with no loader or no state covers nothing); pageless or unknown-type entries are skipped, never terminal; a page that fails to fold is a handler bug (`UNHANDLED_HANDLER_ERROR`, INTERNAL, message `the state fold failed on an event it had accepted`, or `... on an event this command emitted` for COMMUTATIVE's fold of the command's own events), whose ErrorInfo metadata names the page's `sequence` and `type_url` (or, when the fold could not say, the batch's `first_sequence` and `last_sequence`), the `state_type_url` the rebuilder declares (`Rebuilder::of_message`, `with_state_type`) and the fold's own text as `fold_message`; a snapshot the loader cannot load fails with `PERSISTED_EVENT_CORRUPT`; a batched fold (`Rebuilder::with_fold`) gets every uncovered page in one call. Across the C ABI, aggregate and process-manager state is router-owned: a serialized `Any` of the registered state type, the delivered snapshot's state as the initial value, folded by one stateless host fold call per rebuild and handed to every decide / fact / PM callback; a failing host fold answers a `FoldFailure` (the failing page's index in the batch) and is never called again |
| Aggregate dispatch | `CommandHandlerService.Handle` is the only input: envelope, body arm and type validate BEFORE rebuild (unknown command → `NO_HANDLER_REGISTERED`, INVALID_ARGUMENT); handlers receive `CommandContext` (next sequence, had-prior-events, the handled cover); the emitted book passes through as the handler returned it (the coordinator stamps sequences and meta) |
| Reaction commands | Saga and process-manager commands pass through as the handler emitted them: the coordinator stamps their identity, causation and correlation. A saga handler sees the triggering page's cover and sequence; a process-manager handler sees the trigger cover |
| Saga dispatch | EVERY page of the source book dispatches; undeclared types are skipped (C-0051) |
| Facts | A fact arrives in the Fact arm of the command page and runs the fact handler registered for its type; a type with none (a command type included: the arm must match the handler's kind) is `NO_FACT_HANDLER` (INVALID_ARGUMENT) before any rebuild, so nothing is recorded. Otherwise the handler sees the rebuilt state and returns the fact to record (it may annotate it, never refuse it) followed by events that flag it; they come back as the response's events, payloads only. Facts route by (cover domain, fact type), else to the domain's first aggregate, which refuses them. There is no Replay |
| Command upcasting | Command and fact payloads run through the aggregate's upcaster chains before dispatch; a refusal names the sent type URL, its extras the chain's last (`upcast_type_url`); routing tries the sent type, then the aggregate of the domain whose chain serves it (docs/design-handling.md) |
| Conflicts | Handlers see the resolved `Handling` (`expected_sequence`, `conflict_resolution`). AGGREGATE_HANDLES hands the window and nonce in `CommandContext.conflict`; output without `resolve_conflicts(window, nonce)` on exactly that nonce is discarded: `CONFLICT_UNRESOLVED` (ABORTED). COMMUTATIVE runs in the router over the generated `changed()`: decide on the head, keep the events iff `changed(expected, head)` and `changed(head, head + events)` do not overlap, else `CONFLICT_OVERLAP` (ABORTED); none registered: `CONFLICT_RESOLUTION_UNSUPPORTED` |
| Rules version | Every `CommandHandlerResponse` and `ProcessManagerHandleResponse` carries the binary's declared rules version, overwriting a handler's; co-hosted PMs share it. Snapshot selection is the coordinator's (decision 14.1) |
| Process manager | The newest page of the trigger book dispatches; handlers receive the trigger cover; co-resident PMs are selected by identity first — a process state reaches the PM owning its cover domain — and otherwise every PM consuming the trigger domain; responses merge in registration order. Process events pass through as emitted (the coordinator addresses and stamps them) |
| Projector | Folds every page into one projection instance, each fold seeing the book cover and the page's sequence; undeclared domains fold nothing (C-0032), and a projector declaring `"*"` consumes every domain; unmatched types are skipped with a WARN; a failing fold is a handler bug (INTERNAL), named as a failing state fold is, with the projection type (`with_projection_type`) as `state_type_url`. Across the C ABI the projection is router-held (a serialized `Any` of the registered projection type, empty at first), folded by one stateless batched host fold call per delivery, and the router builds the `Projection` (cover, projector name, next sequence after the last page) |
| Type URLs | Emitted type URLs use the bare `/` prefix; incoming ones match by the fully-qualified name after the last `/`, whatever the prefix |
| Errors | One `map_handler_error` table: rejections keep their gRPC code, a command or fact type URL no handler claims → INVALID_ARGUMENT (`NO_HANDLER_REGISTERED` or `NO_FACT_HANDLER`, message `no handler for type URL <url>`), any other `NO_HANDLER_REGISTERED` (no component for the request) → UNIMPLEMENTED, `PERSISTED_EVENT_CORRUPT` (an unloadable snapshot) → DATA_LOSS, `CONFLICT_UNRESOLVED` and `CONFLICT_OVERLAP` → ABORTED, other coded client errors → INVALID_ARGUMENT, unclassified → INTERNAL + `UNHANDLED_HANDLER_ERROR`. Codes ride a `google.rpc.ErrorInfo` detail (domain `angzarr.io`); assertions key on codes, never message substrings |

Not provided here: gRPC serving, health/readiness and transport
configuration, and CloudEvents. Those remain with the host application or the client-*
libraries.

## Testing

- `just test`: the core unit bank, the FFI's raw-pointer ABI consumer test
  (`crates/router-ffi/src/lib.test.rs`), and the conformance features
  driven natively by cucumber-rs (`crates/conformance`), including angzarr-project's handler-contract tier (`features/handler-contract/handling.feature`, bound by scenario id from the submodule).
- `just <lang>-binding-test` (parked at ABI 3, not run in CI): the same `conformance/features` run through
  each binding against fixtures implementing the generated handler
  interfaces from `conformance/proto/test/counter/counter.proto`, plus
  binding-local tests.
- `just mutation-test`: cargo-mutants over the core modules, the FFI
  registry and the architecture linter.
- `just archlint`: the layering above as checked rules — `archlint.toml`
  (engine below the C ABI, components independent of each other and of the
  router, conformance on the public surfaces, bindings as leaves), enforced
  by `tools/archlint` over every module's `use`/path references and every
  manifest dependency. Runs in pre-commit and CI.
